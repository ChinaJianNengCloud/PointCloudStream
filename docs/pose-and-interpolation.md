# 位姿表示与轨迹插值

位姿模块为标定板跟随、模型动作累积和轨迹处理提供统一的空间运算。其关键是明确平移与旋转的表示、变换的作用方向，以及增量在哪个坐标系中定义。轨迹插值进一步将稀疏示教点转换成供回放使用的目标序列。

## 实现与类型边界

| 实现 | 能力与使用位置 |
| --- | --- |
| [app/utils/robot/pose.py](../app/utils/robot/pose.py) | 主入口与标定板跟随使用的 `Pose`；同文件包含 TCP 位姿插值函数 |
| [app/utils/pose/pose.py](../app/utils/pose/pose.py) | 另一套 `Pose`，额外提供 `from_matrix`、`matrix`、`vtk_matrix` |
| [pose_interpolate.py](../app/utils/pose/pose_interpolate.py) | 关节空间插值，供数据回放调用 |
| [entry.py](../app/entry.py) | `view_predicted_poses()` 使用 `align` 语义累积动作 |

两套 `Pose` 是不同的 Python 类。乘法和增量函数使用各自的 `isinstance()` 检查，不能因为属性相同就交叉混用。需要矩阵转换的调用点还必须选择实际提供该能力的类型。

## 数组、单位与旋转约定

内部位姿由位置 `p` 和四元数 `q` 保存，四元数顺序为 `[w, x, y, z]`。SciPy 调用显式指定 `scalar_first=True`。

| 表示 | 数组排列 | 旋转含义 |
| --- | --- | --- |
| `euler` | `[x, y, z, rx, ry, rz]` | 固定轴 `xyz` 欧拉角 |
| `rotvec` | `[x, y, z, vx, vy, vz]` | 轴角旋转向量 |
| `quat` | `[x, y, z, qw, qx, qy, qz]` | 标量在前的四元数 |

`degrees=False` 是默认值。实现只把 `degrees` 传给欧拉角转换，旋转向量始终按弧度处理。SciPy 的小写 `xyz` 表示外禀旋转序列，与大写内禀序列不同。[SciPy 欧拉角约定](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.from_euler.html)

`Pose` 本身不记录长度单位。控制链将位置解释为米，必须在毫米数据进入该链之前完成转换。数据树将关节弧度换成角度只是显示处理，不能据此改变保存数组的单位。

## 刚体变换的组合与求逆

采用列向量，记 `T_A_B` 为从 B 坐标系到 A 坐标系的变换：

```text
P_A = R_A_B · P_B + p_A_B

T_A_B = [ R_A_B  p_A_B ]
        [   0      1   ]
```

`pose_a * pose_b` 组合两个变换：

```text
R = R_a · R_b
p = p_a + R_a · p_b
```

求逆为：

```text
R_inv = transpose(R)
p_inv = -transpose(R) · p
```

乘法顺序会影响旋转，也会影响平移。不能将两个六维数组直接相加来代替一般的刚体变换组合。

## 增量作用方式

令当前位姿为 `T = (R, p)`，增量为 `D = (Rd, pd)`。`apply_delta_pose()` 实际提供以下规则：

| `on` | 结果旋转 | 结果位置 | 几何含义 |
| --- | --- | --- | --- |
| `base` | `Rd·R` | `pd + Rd·p` | 基座坐标中的左乘变换，当前位置也绕基座原点旋转 |
| `ee` | `R·Rd` | `p + R·pd` | 末端局部坐标中的右乘变换 |
| `align` | `Rd·R` | `p + pd` | 旋转左乘，位置按基座方向直接相加 |
| `align3` | `R·Rd` | `p + pd` | 旋转右乘，位置按基座方向直接相加 |
| `align2` | `Rd·R` | `p + pd` | 通过以当前位置为中心的共轭变换实现，与 `align` 等价 |

`align` 适合表达“沿固定空间方向平移，同时修改姿态”的动作，但它的平移不等于完整左乘变换产生的平移。Agent 返回动作在主入口中使用这一规则，标定板跟随则使用 `ee`。

### 一个平移示例

假设末端已经绕 Z 轴旋转 90 度，位置为 `[1, 0, 0]`，增量是局部 X 方向的 0.1 米且无旋转：

- `ee` 将平移向量随当前旋转变换，结果位置为 `[1, 0.1, 0]`。
- `base` 和 `align` 在该例中结果为 `[1.1, 0, 0]`。

若增量带旋转，`base` 还会旋转当前位置，便不再与 `align` 等价。

## 增量反求与一致性

给定当前 `T` 和目标 `U`，`cal_delta_pose()` 的规则为：

```text
base:   D = U · inverse(T)
ee:     D = inverse(T) · U
align:  Rd = Ru · inverse(R)，pd = pu - p
align2: Rd = inverse(R) · Ru，pd = pu - p
```

`base`、`ee` 和 `align` 的反求与同名应用函数配对。`align2` 的反求采用右侧旋转差，而同名应用采用左乘旋转，二者在一般情况下不是逆操作。反求得到的这类增量对应的是 `align3` 的应用语义；代码没有 `cal_delta_pose(..., on='align3')` 分支。

核对空间算法时，基本不变量是 `T * T.inv()` 为单位变换，以及使用同一语义反求再应用能够恢复目标。涉及旋转时，应比较旋转矩阵或等价旋转，不能只比较欧拉角分量，因为同一旋转可能有不同的角度表示。

## 关节空间的距离参数化

`interpolate_joint_positions_equal_distance()` 接收若干六维关节角 `q_i`，默认按弧度使用。它首先计算相邻配置的欧氏距离并累计：

```text
s_0 = 0
s_i = s_(i-1) + ||q_i - q_(i-1)||₂
```

然后删除累计距离近似相同的点，以满足插值器横坐标递增的要求。对于每个关节分别建立 `interp1d(s, q_j, kind=method)`，再在 `[0, s_last]` 上等间隔选取参数并求值。

这一方法避免了按“关键点编号”均分时长导致的参数密度差异：两个相邻关键点距离越远，在统一累计距离参数中占据的区间越长。

数据回放显式指定 `target_length=7`、`method='quadratic'`。函数自身的默认值为 15 个输出点和三次插值，不能据默认值推断 GUI 的回放行为。

```mermaid
flowchart LR
    A[稀疏关节关键点] --> B[累计六维配置距离]
    B --> C[删除重复距离]
    C --> D[每个关节建立插值函数]
    D --> E[均匀采样距离参数]
    E --> F[目标关节序列]
    F --> G[RobotJointOpThread]
```

## TCP 位置插值与姿态 SLERP

`robot/pose.py` 中的 `interpolate_poses_equal_distance()` 对六维 TCP 位姿使用类似流程，但累计距离只取三维位置：

```text
s_i = s_(i-1) + ||p_i - p_(i-1)||₂
p(s) = 各位置分量的 interp1d 插值
R(s) = Slerp(s_i, R_i) 的插值结果
```

姿态先由欧拉角转换为旋转对象，经 SLERP 插值后再转换回欧拉角。SLERP 在每两个端点之间沿最短旋转路径变化；本函数使用的插值参数是累计位置距离，不是真实时间。[SciPy SLERP 说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Slerp.html)

因此，不能从这里推导机器人具有恒定角速度。当前 GUI 回放也没有调用这个 TCP 插值函数，而是使用关节插值。

## 等距离的实际含义

函数名称中的“等距离”表示对原始折线的累计距离参数进行均匀采样。二次或三次插值会使结果曲线偏离原折线，没有再计算新曲线的真实弧长，因此输出点间的几何距离不一定严格相等。

插值器不提供速度、加速度、关节限位、碰撞或奇异点约束。机器人运动耗时由后续 SDK 的目标执行与运动参数决定。该模块生成目标点列，不是完整的时间参数化运动规划器。

`force_original_points=True` 时，会把原始距离参数与额外均匀样本合并去重。原始点得以保留，但重复端点会减少新增数量，原始点过多时又会超过目标数量，所以输出长度不保证等于 `target_length`。

## 退化输入与边界条件

- 输入少于两个点时直接返回原输入，不扩展到目标长度。
- 总距离为零时重复第一帧。TCP 插值因此会丢弃原地旋转序列中的后续姿态。
- TCP 路径删除重复位置距离时，也会一起删除对应姿态。位置不变但方向变化的关键点不会被保留为独立事件。
- 二次插值需要足够的唯一参数点；两个不同关键点在当前 GUI 的二次插值调用中会报错。回调捕获 `ValueError` 后终止本次回放。
- 三次插值和二次插值都没有按有效点数自动降阶，也没有处理角度跨越周期边界的展开。
- 关节距离直接使用角度数值差，没有关节权重，也没有把跨越 `-π` 与 `π` 的表示差自动识别为短路径。
- 关节函数在总距离非零、但近似去重后仅剩一点的分支中，使用 `joints[0].tolist()` 构造返回值；这不保证得到完整的六维关节配置。

这些条件决定了哪些输入能保留原有运动含义。特别是纯旋转、重复关键点和角度环绕，不应仅依赖目标点数量判断插值有效。
